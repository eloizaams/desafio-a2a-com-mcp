# ADR-0002 — Lado A2A com `a2a-sdk==1.2.2` e estado em memória

- **Status:** aceito · **Data:** 2026-10-05

## Opções
1. **a2a-sdk oficial** — Prós: card v1.0, binding JSON-RPC, `TaskUpdater` (`requires_input`, `complete`, `failed`, `cancel`) e recusa de Task terminal prontos. Contras: modelo AgentExecutor a aprender; possíveis divergências do wire.
2. **JSON-RPC manual em Starlette** — Prós: controle byte a byte. Contras: reimplementa protocolo; mais código e mais risco.

## Decisão
a2a-sdk. Tasks em `InMemoryTaskStore`; pendências MRTR em um store próprio em memória (`task_id → PendenciaMRTR`), separado do TaskStore para que o `requestState` nunca seja serializado em resposta.

## Consequências
Divergência real do SDK frente ao wire → documentar no README com evidência (regra do enunciado). As divergências abaixo são anotadas aqui durante o desenvolvimento (mesmo padrão da ADR-0006) e consolidadas no README na fase 006 (`ENT-01`).

## Notas da fase 004-agente-a2a
- **`a2a-sdk==1.2.2` exige o header `A2A-Version: 1.0` em todo `SendMessage`/`GetTask` (`_process_non_streaming_request`, decorado com `validate_version`), senão recusa com `-32009`.** Ausência de header é tratada como v0.3; `enable_v0_3_compat` só reconhece os nomes de método da v0.3 (`message/send`, `tasks/get`, ...), não os da v1.0 usados aqui — não resolve. Nem `exemplos/wire/08-a2a-send-message.json` nem `validador/validar.py` mandam esse header (não é exigido pelo enunciado). Contorno: `ContextoComVersaoPadrao` (`agente/src/agente_salas/adapters/a2a/contexto.py`), um `ServerCallContextBuilder` que assume `1.0` quando o header vier ausente, passado para `create_jsonrpc_routes(..., context_builder=...)`.
- **`a2a-sdk==1.2.2` não tem `GetTaskResponse`** (só `SendMessageResponse`, que embrulha com `{"task": {...}}`). `GetTask` devolve o `Task` cru direto em `result`, sem o wrapper `"task"` de `exemplos/wire/09-a2a-get-task-input-required.json`. Não há proto `GetTaskResponse` no pacote instalado para corrigir isso sem reescrever o dispatcher do SDK. Sem efeito nos checks: `validador/validar.py` (`tarefa_de()`) já faz `resultado.get("task") or resultado`.
- **O `AgentExecutor.execute()` precisa enfileirar um `Task` completo como primeiro evento**, antes de qualquer `TaskStatusUpdateEvent` — `TaskUpdater.submit()/.start_work()` sozinhos levantam `InvalidAgentResponseError: Agent should enqueue Task before TaskStatusUpdateEvent event`. Usar `a2a.helpers.new_task_from_user_message(context.message)` com `event_queue.enqueue_event(...)` antes de qualquer `updater.*`. Ver `agente/src/agente_salas/adapters/a2a/executor.py`.
